# 💬 Консольный мессенджер на Go

Полнофункциональный мессенджер с консольным интерфейсом, поддерживающий личные и групповые чаты, передачу файлов, историю сообщений и шифрование локальных данных на клиенте.

## 🚀 Возможности

- **🔐 Безопасная авторизация** – пароли хешируются bcrypt на сервере, локальная БД шифруется паролем (AES через BadgerDB)
- **💬 Личные и групповые чаты** – имена групп начинаются с `#`
- **📎 Передача файлов** – с контрольными суммами (SHA-256), прогресс-баром и подтверждением целостности
- **⏳ История сообщений** – хранение на сервере (SQLite) и локально (BadgerDB) с инкрементальной синхронизацией
- **🔄 Reply / Forward** – цитирование и пересылка сообщений с визуальным выделением
- **😊 Поддержка эмодзи** – текстовая замена `:smile:` → 😊
- **🖥️ Консольный интерфейс** – построен на [Bubble Tea](https://github.com/charmbracelet/bubbletea) + [Lipgloss](https://github.com/charmbracelet/lipgloss)
- **🔒 TLS-шифрование трафика** – самоподписанные сертификаты с авто-генерацией
- **🛡️ Graceful shutdown** – сервер корректно завершает работу, уведомляя клиентов

## 🔧 Зависимости

- **Go 1.21+**
- [Bubble Tea](https://github.com/charmbracelet/bubbletea) – TUI-фреймворк
- [Lipgloss](https://github.com/charmbracelet/lipgloss) – стилизация терминала
- [BadgerDB v4](https://github.com/dgraph-io/badger) – встраиваемая key-value БД (клиент)
- [SQLite (modernc.org/sqlite)](https://modernc.org/sqlite) – чистая Go-реализация SQLite (сервер)
- [bcrypt](https://pkg.go.dev/golang.org/x/crypto/bcrypt) – хеширование паролей

## ⚙️ Запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/nurenurenure/go_messenger
cd messenger
```

### 2. Запустить сервер
```bash
go run ./cmd/server
```
Сервер автоматически сгенерирует TLS-сертификаты (server.crt, server.key), если их нет, и запустится на localhost:8080.

### 3. Запустить клиент(ы)
В другом терминале:
```bash
go run ./cmd/client
```
Ввести никнейм и пароль. Если пользователь новый, он зарегистрируется автоматически.

## 🕹️ Управление (клиент)
### Навигация и чаты
Tab – переключение между чатами (циклический выбор)

↑ / ↓ – перемещение по истории сообщений (режим Reply)

→ (в режиме Reply) – переслать выбранное сообщение (Forward)

Ctrl+C – выход

### Команды (ввод в строке сообщения)
/add <никнейм> – добавить контакт в список чатов

/join #<имя_группы> – присоединиться к групповому чату

/leave <никнейм_или_#группа> – выйти из чата и заблокировать сообщения (для личных чатов – игнорирование)

/file <получатель> <путь> – отправить файл

### Эмодзи
Синтаксис: :smile:, :heart:, :thumbsup: и т.д.

Tab после двоеточия и начала названия включает автодополнение (например, :smi + Tab → :smile:)

### Другие сочетания
Enter – отправить сообщение

В режиме Reply выделение сбрасывается после отправки，при выходе за границы списка стрелкой вниз или нажатием Esc.

## 🧩 Протокол передачи данных

Бинарный заголовок (5 байт: 4 байта длина + 1 байт тип) + JSON-тело.

Типы сообщений:

0x01 Auth

0x02 Chat

0x04 System (LEAVE, JOIN)

0x10–0x16 File transfer (Request, Accept, Reject, Header, Chunk, Complete, Error)

## 📌 Примечания

Сервер использует store-and-forward для файлов: временно сохраняет чанки на диск и в память, после успешной передачи удаляет.

Локальная БД клиента шифруется паролем пользователя (SHA-256 → ключ шифрования BadgerDB).

lastSyncTime хранится в открытом текстовом файле (user_data/sync_<username>.txt) для доступа до ввода пароля.

Все ошибки сети отображаются в чате как системные сообщения.
